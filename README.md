User Authentication System

Простой и безопасный проект на Python для регистрации и аутентификации пользователей с использованием PostgreSQL.
Для хэширования паролей применяется Argon2 — современный и надёжный алгоритм с солью и настраиваемыми параметрами. Все SQL‑запросы выполняются параметризовано, что предотвращает SQL‑инъекции.

🔹 Ключевые возможности

Регистрация и вход пользователей через командную строку

Безопасное хранение паролей с Argon2 (с солью и параметрами безопасности)

Защита от SQL‑инъекций — все запросы параметризованы (%s)

Интерактивное меню; ввод пароля через getpass (оно не отображается в терминале)

Лёгкая настройка и запуск

🛠 Установка и настройка
1. Клонируйте репозиторий
git clone https://github.com/USERNAME/REPO_NAME.git
cd REPO_NAME

2. Создайте и активируйте виртуальное окружение
python -m venv venv

# Windows
venv\Scripts\activate

# Linux / macOS
source venv/bin/activate

3. Установите зависимости
pip install -r requirements.txt


requirements.txt должен содержать минимум:

psycopg2-binary
argon2-cffi

4. Настройка подключения к PostgreSQL

Есть два варианта — хранить параметры прямо в auth.py (не рекомендуется для продакшена) или использовать переменные окружения / ввод пароля при запуске.

Пример безопасной конфигурации (в auth.py) — чтение пароля из переменной окружения или запрос через getpass:

import os
import getpass

DB_HOST = os.getenv('DB_HOST', 'localhost')
DB_NAME = os.getenv('DB_NAME', 'testdb')
DB_USER = os.getenv('DB_USER', 'postgres')
DB_PASSWORD = os.getenv('DB_PASSWORD') or getpass.getpass("Введите пароль БД: ").strip()


Убедитесь, что база данных существует. Если нет — создайте её (в psql или pgAdmin):

CREATE DATABASE testdb;

🚀 Запуск
python auth.py


При запуске появится меню:

Выберите действие:
1 - Регистрация
2 - Вход
3 - Выход


Регистрация — вводите логин и пароль (пароль вводится через getpass и не виден в терминале).

Вход — вводите логин и пароль для проверки.

Выход — завершение работы программы.

🔒 Как обеспечена безопасность

Argon2 используется для хэширования паролей: соль генерируется автоматически, параметры времени/памяти/параллельности можно настраивать.

Пароли не хранятся в открытом виде — в БД сохраняется только строковое представление Argon2‑хэша.

Параметризованные запросы (cur.execute("... %s ...", (value,))) предотвращают SQL‑инъекции — пользовательский ввод не может изменить структуру SQL.

Рекомендуется хранить конфиденциальные настройки (пароли, хосты) в переменных окружения или в .env (и добавлять .env в .gitignore).
